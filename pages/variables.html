Переменные: let и const

Блочная область видимости и иммутабельность

Проблема старого подхода

Одним из первых и наиболее важных улучшений ES6 стало введение ключевых слов let и const, которые пришли на смену var. До ES6 var был единственным способом объявления переменных, но он обладал функциональной областью видимости и мог приводить к запутанному поведению из-за поднятия (hoisting) и случайного повторного объявления.

Классическая проблема — утечка переменной за пределы блока if или for:

if (true) {
    var message = "Привет";
}
console.log(message); // "Привет" — переменная «утекла» наружу

Такое поведение часто приводило к трудноуловимым багам, особенно в больших функциях с множеством блоков.

Ключевое слово let

let позволяет объявлять переменные с блочной областью видимости — они доступны только внутри блока кода, в котором были объявлены. Блоком считается всё, что находится внутри фигурных скобок: тело if, for, while или просто отдельный { }.

if (true) {
    let message = "Привет";
    console.log(message); // "Привет"
}
console.log(message); // ReferenceError: message is not defined

Переменную, объявленную через let, можно переприсваивать:

let count = 0;
count = 1;
count = 2;
console.log(count); // 2

Ключевое слово const

const также использует блочную область видимости, но запрещает повторное присваивание значения. Это помогает избежать случайных изменений и делает код более предсказуемым.

const PI = 3.14;
PI = 3.15; // TypeError: Assignment to constant variable

Важно: const не делает объект или массив «замороженным». Нельзя переприсвоить саму переменную, но содержимое объекта или массива менять можно:

const user = { name: "Иван" };
user.name = "Пётр"; // OK — меняем свойство объекта
user = {};          // Ошибка — нельзя переприсвоить переменную

const list = [1, 2, 3];
list.push(4);       // OK — мутируем массив
list = [];          // Ошибка — нельзя переприсвоить переменную

Сравнение: var, let, const

Сравнение способов объявления переменных
Характеристика var let const
Область видимости Функциональная Блочная Блочная
Поднятие (hoisting) Да Да (но TDZ) Да (но TDZ)
Переприсваивание Да Да Нет
Повторное объявление Да Нет Нет
Рекомендация Не использовать По необходимости По умолчанию

Лучшая практика

Используйте const по умолчанию и прибегайте к let только тогда, когда переменной действительно нужно присвоить новое значение. Такой подход:

  • снижает количество случайных изменений;
  • делает намерения автора кода явными;
  • упрощает чтение и отладку;
  • предотвращает целый класс ошибок, связанных с переприсваиванием.

Ключевое слово var в современном коде не используется — оно оставлено исключительно для обратной совместимости со старыми скриптами.
