Промисы и async/await

Асинхронное программирование в современном стиле

Проблема колбэков

До ES6 асинхронные операции обрабатывались через колбэки, что часто приводило к «аду колбэков» (callback hell) — глубоко вложенным, трудным для чтения и поддержки конструкциям.

getUser(id, (user) => {
    getOrders(user.id, (orders) => {
        getDetails(orders[0].id, (details) => {
            console.log(details);
        });
    });
});

Чем больше шагов — тем глубже вложенность и тем сложнее обрабатывать ошибки.

Промисы (Promises)

Промисы появились в ES6 как объекты, представляющие eventual completion (или failure) асинхронной операции. Они позволяют организовать асинхронный код более линейно.

Создание промиса

const promise = new Promise((resolve, reject) => {
    const success = true;
    if (success) {
        resolve("Данные получены");
    } else {
        reject("Ошибка");
    }
});

Обработка через .then() и .catch()

promise
    .then((result) => {
        console.log(result); // "Данные получены"
    })
    .catch((error) => {
        console.error(error);
    })
    .finally(() => {
        console.log("Операция завершена");
    });

Цепочки промисов

Плоский стиль вместо вложенных колбэков:

getUser(id)
    .then((user) => getOrders(user.id))
    .then((orders) => getDetails(orders[0].id))
    .then((details) => console.log(details))
    .catch((error) => console.error(error));

async/await

В ECMAScript 2017 появились async-функции и ключевое слово await — синтаксический сахар над промисами. async превращает обычную функцию в асинхронную, оборачивая возвращаемое значение в Promise. await приостанавливает выполнение функции до разрешения промиса.

async function loadData() {
    try {
        const user = await getUser(id);
        const orders = await getOrders(user.id);
        const details = await getDetails(orders[0].id);
        console.log(details);
    } catch (error) {
        console.error(error);
    }
}

loadData();

Такой код читается как синхронный, но выполняется асинхронно. Это значительно улучшает читаемость и поддерживаемость.

Возврат значения

Любая async-функция возвращает промис, даже если вы возвращаете обычное значение:

async function getValue() {
    return 42;
}

getValue().then((v) => console.log(v)); // 42

Параллельное выполнение: Promise.all

Если несколько асинхронных задач не зависят друг от друга — запускайте их параллельно через Promise.all(), а не последовательно через await:

// Медленно — ждём по очереди
const user = await getUser();
const posts = await getPosts();

// Быстро — параллельно
const [user, posts] = await Promise.all([
    getUser(),
    getPosts()
]);

Другие комбинаторы

  • Promise.allSettled() — ждёт все промисы и возвращает массив результатов (успешных и отклонённых).
  • Promise.any() — возвращает результат первого успешно завершившегося промиса.
  • Promise.race() — возвращает результат первого завершившегося (неважно, успех или ошибка).

Сравнение стилей

Колбэки vs Промисы vs async/await
Стиль Читаемость Обработка ошибок
Колбэки Низкая (вложенность) Сложная
Промисы Средняя Через .catch()
async/await Высокая Через try/catch

Лучшие практики

  • Предпочитайте async/await вместо цепочек .then() — код линейнее и легче отлаживается.
  • Всегда оборачивайте await в try/catch — иначе ошибка «упадёт» в необработанный промис.
  • Не используйте await внутри циклов, если итерации независимы — вместо этого Promise.all().
  • Помните: await можно использовать только внутри async-функции (или на верхнем уровне модуля с ES2022).
  • Не забывайте про .finally(), если нужно что-то выполнить независимо от результата.

Совет

Если try/catch становится огромным — вынесите каждый await в отдельную маленькую функцию. Такой код проще тестировать.
